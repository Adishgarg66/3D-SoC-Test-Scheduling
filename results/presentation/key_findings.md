# Key Verified Experimental Findings (Presentation & Viva Summary)

1. **H-MACO-FA Hybrid Performance Under Fair Evaluation Budget (`max_evals=300`, 10 seeds)**:
   - **Evaluation Budget Methodology**: All five stochastic metaheuristics (`ABC`, `Bat`, `Firefly`, `MACO`, `H-MACO-FA`) share the exact `max_evals=300` schedule-evaluation budget cap (`Mean Evals = 300.0`). `Greedy` is a deterministic non-iterative Longest-Processing-Time (LPT) list-scheduling heuristic that executes once per benchmark (`1` evaluation), serving as the un-iterated deterministic lower-effort baseline.
   - On Fixed 3D `p22810`, **H-MACO-FA** achieved Mean = `436,173.20` cycles (Best = `435,099`, Std = `594.27`), outperforming Greedy Baseline (`449,348.00`) and MACO (`436,663.30`), with Peak Power `52.3W <= 94.05W`, Peak Tj `83.64°C < 95.0°C`, and TSVs `24/24` (`Safe`).
   - On Random 3D `p22810`, **H-MACO-FA** achieved Mean = `418,023.20` cycles (Best = `416,648`, Std = `1136.31`), achieving `7.31%` mean makespan reduction vs Greedy.
2. **Real Physical Hardware Validation (`Raspberry Pi 4 Model B Rev 1.4`)**:
   - Verified `is_physical_hardware = True` via `RPi.GPIO` over TCP socket HIL (`raw_data/raspberry_pi/rpi_ping_verification.json`).
   - Recorded 3 physical trials for every architecture/benchmark pair (`18` total live hardware executions) with UTC timestamps, per-core GPIO event logs, client roundtrip latency, and Linux sleep jitter.
   - **Critical HIL Timing Distinction (Sequential GPIO Replay vs Concurrent SoC Simulation)**: The simulated SoC scheduler executes non-conflicting cores **concurrently** (`makespan < sum(core durations)`), whereas the physical Raspberry Pi HIL server replays each scheduled core **sequentially** (`for task in tasks:`) on GPIO pins (`wall_clock ≈ cumulative_task_cycles × time_scale + OS/GPIO jitter`). Measured physical Pi server wall-clock (`1.4160s` mean on `d695`, `3.7381s` mean on `p22810`; client TCP roundtrip `1.481s` / `3.792s`) validates exact cumulative cycle replay time + sub-0.2% Linux/GPIO jitter against expected sequential task sleep sums, rather than modeling simultaneous silicon ATE channels.
3. **Genuine ML Thermal Regression — Deduplicated Split & Unseen Solver Trajectories (No Physical Thermal Sensor)**:
   - Trained architecture-matched Linear (`d=1`) and Polynomial Ridge (`d=2`) models on unique active-core states generated by 3D RC thermal reference models (`seed=42`, strictly deduplicated before train/test split so `train_test_overlap = 0`).
   - **Random 3D RC (`ThermalModel`)** [`1113` train / `279` unique test]: Linear (`d=1`) Test MAE = `2.0185°C`, R² = `0.998772`; Polynomial (`d=2`) Test MAE = `1.566°C`, RMSE = `2.1283°C`, Max Err = `8.2673°C`, R² = `0.999234`.
   - **Fixed 3D RC (`FixedThermalModel`)** [`1113` train / `279` unique test]: Linear (`d=1`) Test MAE = `1.4844°C`, R² = `0.999201`; Polynomial (`d=2`) Test MAE = `0.8955°C`, RMSE = `1.1334°C`, Max Err = `3.5219°C`, R² = `0.99973`.
   - **Independent Unseen Solver Schedule Trajectories (`seeds=512,777,1024`, Bat/MACO/H-MACO-FA)**: On strictly unseen active-core steps (`0%` training overlap), Polynomial Ridge (`d=2`) achieved MAE = `1.0709°C`, RMSE = `1.3571°C`, R² = `0.987863` on Random 3D (`n=90` steps) and MAE = `0.8506°C`, RMSE = `1.0421°C`, R² = `0.988331` on Fixed 3D (`n=85` steps).
